# 扩卡验收用例 v1

依据：小喇叭《扩卡清单-v1.md》（SHA256 `04c06f29d8c1fb4bd404f21f13374f47c2af607e3b5d66cb788baed5061e2e69`），逐行转成 `expansion-cards.json`，100 张：公共 20 + 八职业各 10（随从 5、法术 5）。
清单只是炉石参考：卡名、数值、做不做由熊大定。所以数值以 `EXPANSION_CARD_IDS` 里登记的设计稿值为准，没登记的才按清单值验。

## 跑法

```
node --test tests/expansion/expansion.test.mjs
EXPANSION_CARD_IDS=ids.json node --test tests/expansion/expansion.test.mjs
```

`ids.json`：`{"neutral-01":"cardId"}`，或 `{"neutral-01":{"id":"cardId","cost":1,"attack":1,"health":1}}`。key 见下表。

## 判定

- 前置不满足 → `FAIL 未实现：<缺什么>`；口径没定 → `FAIL 待定口径`。不跳过，不判通过。
- 只写测试，不改产品代码。

## 用例（共 328 条）

| 组 | 条数 | 查什么 |
|---|---:|---|
| G1–G2 清单自检 | 2 | 100 张、每职业 5+5、公共全随从、美术描述 1–40 字。应该过 |
| G3 职业注册 | 8 | 八职业已注册，默认卡组 30 张且 `validateDeck` 合规 |
| M 机制 | 18 | 每个机制至少一张卡已登记；卡面文字写出关键词；行为断言等熊大定口径 |
| X 定义 | 100 | 已登记、在 `CARDS`；类型、费用、身材；卡名原创（不是炉石中英文名）；卡面写出关键词（冲锋、嘲讽、战吼等）；`CARD_METADATA` 职业归属；能放进本职业卡组、别的职业带不了 |
| X 卡图 | 100 | `ART_BY_SOURCE_ID` 有登记、图片文件存在、登记名和卡名一致、有 `artBrief` |
| X 目标 | 100 | 10 费、双方各一个满血和受伤随从时，`legalActions` 给出的合法目标集合和清单「目标」列一致；无目标卡不能要求选目标；抉择卡 7 张判待定口径 |

## 现在跑的结果

328 条：过 6（G1、G2，现有四职业的 G3），不过 322，退出码 1。不过的全是 `FAIL 未实现`（卡 id 未登记 / 新四职业未注册）或 `FAIL 待定口径`；没有跳过，也没有 TypeError、ReferenceError、SyntaxError。

## 要熊大定

1. 每张卡登记 id 到 `ids.json`，数值改了就一起写进去。
2. 抉择的接口：先选项还是先选目标，取消怎么回退（7 张卡的目标用例等这个）。
3. 各机制的行为口径：战吼、亡语、沉默、冻结、光环、激怒、风怒、奥秘、发现、法术伤害的触发时机、叠加、被沉默后是否失效。过载、连击、抉择、潜行沿用 `tests/classes/README.md`。
4. 清单里注明的破例卡：寒冰护体（奥秘）、恶魔之火和感知恶魔（要恶魔种族）、炎爆术（10 费）、象牙骑士等随机卡（要能重放复现）。
