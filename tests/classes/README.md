# 四职业规则验收用例大纲：牧师 / 潜行者 / 德鲁伊 / 萨满

> 板砖写，2026-10-11。依据：小喇叭 `四职业资料.md`（2026-10-11 00:20，HearthstoneJSON build 253932 经典复刻口径）。
> 这是验收大纲，不是规则签收；最终数值、客人对应和是否纳入「经典扩展」层，以熊大设计稿和杨总决定为准。
> 只写 md，没改 cardcore、没改游戏代码。

## 0. 干净失败的约定

现状（main `30964c8`，`preview/cards/cardcore.mjs` `RULES_VERSION=bookstore-tech-0.6.0`）：
- `HEROES` 只有 `warrior / mage / paladin / warlock`；
- 关键词只有 `charge / taunt`；效果种类只有 `areaDamage / draw / damage / heal / mana`；
- 命令字段白名单：`commandId expectedRevision player type source target position cards _ai`，没有「抉择」用的字段。

实测（node 24.19）：
```
createGame({heroes:['priest','mage']})  -> Error: Invalid heroes
defaultDeck('priest') / deckCapacity('priest') -> Error: Invalid hero class
（rogue / druid / shaman 同样）
```

所以每条用例都按下面的规则判：
1. **先查前置**：职业已注册（`HEROES[classId]` 存在）、所需关键词或效果已存在。前置不满足时，判 `FAIL 未实现：<缺什么>`。不判 ERROR，不跳过，更不判通过。
2. **前置满足后**，再断言下表的「期望」；断言不过就判 `FAIL 产品`。
3. 随机都走 `rulesSeed`，同一 seed 用 `replay()` 重放，结果和 `hashState` 必须一致。
4. 每条记录：seed、命令序列、`apply` 返回的 `error.code` 和 events。

用例 ID 后的标记：
- **[基础]**：属于 Basic 卡池或英雄技能。
- **[经典]**：机制只在经典扩展里，例如过载、连击、抉择、潜行。要等杨总或熊大定了纳入，才算必过；定之前照跑，但只记结果。
- **[未核对]**：资料里也没核实，要熊大在设计稿里定口径。

## 1. 通用（四职业都跑）

| ID | 用例 | 期望 |
|---|---|---|
| C1 [基础] | 注册 | `HEROES` 含 4 个新职业，名字用店铺客人原型，不用炉石英雄名 |
| C2 [基础] | 默认卡组 | `defaultDeck(classId)` 30 张，`validateDeck` 通过；混入别的职业的卡就报 `WRONG_CARD_CLASS` |
| C3 [基础] | 英雄技能费用和次数 | 2 费；同一回合第 2 次报 `POWER_USED`；法力不足 2 时报 `NOT_ENOUGH_MANA`，法力不扣 |
| C4 [基础] | 技能目标字段 | 需要目标的技能（牧师）不带 target 报 `INVALID_TARGET`；不需要目标的技能（潜行者、德鲁伊、萨满）带 target 报 `UNEXPECTED_TARGET` |
| C5 [基础] | 对战 AI | `chooseAIAction` 在 4 个新职业下 20 回合内不出 `AI_NO_COMMAND`，也不出非法命令 |
| C6 [基础] | 存档与重放 | `serialize` 后 `deserialize` 结果一致；`replay(getReplay(g))` 的哈希和原局一致 |
| C7 UI | 卡牌文字 | 手牌里的冲锋、嘲讽、过载（X）、连击、抉择、潜行要写在卡面上，不用点开详情就能看到 |
| C8 UI | 英雄技能 | 技能按钮上能看到费用、效果；是否需要选目标也要写明 |

## 2. 牧师（治疗、生命值）

| ID | 用例 | 期望 |
|---|---|---|
| P1 [基础] | 技能治疗受伤的己方英雄，30 血里剩 27 | 回到 29，events 里有 heal，数值 2 |

| P6 [基础][未核对] | 北郡牧师：满血随从被治疗 | 实际回了血才抽牌；满血时治疗不抽牌。口径待熊大定 |
| P7 [基础] | 神圣之灵 | 生命值翻倍（当前生命和上限都翻倍）；翻倍后再治疗，以新上限为准 |
| P8 [基础] | 暗言术：痛和暗言术：灭 | 攻击力 ≤3 和 ≥5 的边界：3 和 5 合法，4 报 `INVALID_TARGET` |

## 4. 德鲁伊（护甲、法力水晶；抉择）

| ID | 用例 | 期望 |
|---|---|---|
| D1 [基础] | 技能 | 本回合英雄攻击 +1，护甲 +1 |
| D2 [基础] | 回合结束 | 加的攻击回到 0（有武器就回到武器攻击）；护甲保留 |
| D3 [基础] | 护甲抵伤 | 先扣护甲，再扣 hp；`absorbed` 数值正确 |
| D4 [基础] | 激活 | 本回合多 2 点可用法力；下回合不保留；`maxMana` 不变 |
| D5 [基础][未核对] | 激活后法力超过 10 | 封顶 10，还是可以临时超过，等熊大定 |
| D6 [基础] | 野性成长 | `maxMana+1`，但本回合可用法力不加（空水晶）；下回合正常回满 |
| D7 [基础][未核对] | 10 个水晶时野性成长 | 不再加水晶；要不要给替代牌，等熊大定 |
| D8 [经典] | **抉择：二选一** | 出牌命令要带选项；不带选项、或带了不存在的选项，都报错，牌留在手上，法力不扣 |
| D9 [经典] | 抉择只结算选中的那个效果 | 例如愤怒选了 3 点伤害，就没有抽牌 |
| D10 [经典] | 抉择选完才算打出 | 取消选择后牌和法力都不变；连击计数也不增加 |
| D11 [经典] | 命令格式 | 现在的命令字段白名单里没有抉择字段。新增字段要改白名单，同时更新 `UNKNOWN_FIELD` 的回归用例，不能直接放开白名单 |
