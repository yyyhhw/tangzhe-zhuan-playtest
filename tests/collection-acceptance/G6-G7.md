## G7 真浏览器冒烟（5 条）

环境：preview 父页 + 卡牌收集页，真实主档 `tangzhe-save`，钱包走 CardHost。每条开始前先导出主档原文，记下 SHA256。

| # | 步骤 | 期望 | 证据 |
|---|---|---|---|
| S1 单抽扣款 | 金币 ≥ 500 万，空收藏，点一次抽卡 | 经营金币正好少 500 万；收藏 +1；凭据里扣费 5,000,000，且 committed=true；只写主档 `state.collection`，根 key 只有 `tangzhe-save` / `-bak` / `-tab-lock` | 前后余额、导出、根 key 列表 |
| S2 溢出弹窗 | 已有一张传说满 2 张，粉尘 = 上限 − 399；抽卡 → 取消；再抽卡 → 勾「以后不再提醒」→ 继续 | 弹窗文案逐字为「超出上限的粉尘会消失，是否继续抽卡？」，「以后不再提醒」默认不勾；点取消零写入、不扣费。继续后只扣 1 次，g/a/o 和凭据一致；刷新后不再弹。空收藏且粉尘已满时不弹（风险口径） | 截图 + 前后导出 |
| S3 写档失败不写入 | 用 DevTools 让 `localStorage.setItem` 抛出 QuotaExceeded，然后抽卡 | 提示写档失败；金币、收藏、粉尘、凭据都不变；恢复写入后，同一 txId 只提交 1 次 | 前后主档 SHA256 相同 |
| S4 刷新不重复扣 | 抽卡后，在提交返回前刷新或关闭标签，再重开 | 按同一 txId 恢复为已提交，或者恢复为未扣费，二者只会有一种；不重抽，不换 cardId 或 foil；余额只少 0 或 500 万 | 账本 + 余额 |
| S5 跨标签 | A、B 两个标签同时打开；A 的弹窗开着时，B 抽一次；然后 A 点继续 | A 报冲突，零写入，重读后再判断；两边总扣费等于 500 万 × 成功抽数 | 两边导出 + writes |

熊大提的边界，S3–S5 要重点看：
- `E.transact` 是先扣款、再执行 apply，所以去重必须在外层共同锁内、扣款之前做。重放同一 txId 时，余额不能变。
- preview 父页还是旧的存档实现，普通经营写档也没有统一 Web Lock。S5 要加一组：B 标签做一笔普通经营写档（不是抽卡），看 A 的抽卡结果会不会被覆盖。

## G7 冒烟骨架：`smoke_g7.py`

跑法：`python3 tests/collection-acceptance/smoke_g7.py <收集页 URL>`。退出码：0 = 全通过且用的是真实经营钱包；1 = 有失败；3 = 没有失败，但有跳过或用的是模拟钱包，不算 G7 通过。

用参考页（模拟钱包）把步骤跑通，WebKit 和 Chromium 各跑一遍：通过 12，失败 0，跳过 6，rc=3，**模拟≠真实经营**。
跳过的 3 项，每个引擎各 1 次：
- S1b 根 key：依赖 G4 CardHost
- S4b 同一 txId 重放：缺 `CollectionQA.replayTx`
- S5b 普通经营写档并发：缺 `CollectionQA.economyWrite`，依赖 G4 父页

S5 的通过标准：A 报冲突，或者按同一 txId 返回原来的结果，两种都算通过；两个标签加起来只能扣 1 次。
