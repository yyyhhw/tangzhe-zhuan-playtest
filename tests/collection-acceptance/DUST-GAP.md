# 「粉尘差额写 / 不写」验收预备口令

本页只写测试侧 md，断言还没有写进脚本。产品代码没改，v10a 没碰，也不替杨总拍板。
对照小喇叭的《粉尘不够镀金UI提示文案草案》。他的「写 / 不写」两版玩家提示交过来以后，下表的占位文案换成原文，断言逻辑不变。

## 骨架现状（v1.1 `model.mjs` `gildQuote`，第 81–86 行）
报错按下面的顺序检查，命中第一个就抛出：
1. `CARD_NOT_IN_CONFIGURED_POOL`
2. `NO_NORMAL_COPY_TO_GILD`
3. `INSUFFICIENT_DUST`
4. 发起时还有别的交易没结束，报 `ACTIVE_TRANSACTION_PENDING`（第 189、227 行）

两个缺口：
- **抛错时不返回所需粉尘和差额**，界面只能自己用 `rarities[].gildDustCost − 当前粉尘` 去算。
- `NO_NORMAL_COPY_TO_GILD` 有两种情况：还没抽到这张卡、这张已经全是金色。两种用的是同一个报错，界面要看持有情况自己区分。

## 共用断言：两版都要过，不管拍哪版
| 编号 | 前置 | 期望 |
|---|---|---|
| D0-1 | 4 种拒绝都各跑一次 | 粉尘、收藏、回执、偏好都不变，零写档，revision 不变 |
| D0-2 | 粉尘正好等于镀金价 | 能镀金，镀完粉尘为 0（边界值） |
| D0-3 | 粉尘 = 镀金价 − 1 | 报 `INSUFFICIENT_DUST`，按钮置灰 |
| D0-4 | 拒绝原因显示 | 4 种原因的提示文字互不相同；「没抽到」和「已全金」也分开显示 |
| D0-5 | 按钮旁常显「需要 {价} · 你有 {当前}」 | {价} 等于配置里的 `gildDustCost`，{当前} 等于存档里的粉尘值。两版都适用（这是草案建议，待拍） |

## A 版：写差额（小喇叭建议）
| 编号 | 前置 | 期望 |
|---|---|---|
| DA-1 | 粉尘 1599，传说镀金价 1600 | 文字里出现「还差 1」，界面上的差额 `data-dust-short` = 1 |
| DA-2 | 粉尘 0，普通卡镀金价 {待定} | 差额等于镀金价 |
| DA-3 | 抽一次卡、粉尘增加后不刷新页面 | 差额跟着变小；粉尘够了以后差额文字消失，按钮可以点 |
| DA-4 | 其他 3 种拒绝原因 | **不出现**「还差」这几个字 |

## B 版：不写差额（炉石做法）
| 编号 | 前置 | 期望 |
|---|---|---|
| DB-1 | 粉尘不够 | 只写「粉尘不足」，**不出现**「还差」和任何差额数字 |
| DB-2 | 同上 | D0-5 的常显那行照常显示，如果拍了要它 |

## 怎么判
- 规则层（Node）：D0-1 到 D0-3 直接调用骨架的 `gild` 和 `quote` 判，预计新增 3 条，两版共用。
- 界面层（Playwright，`ui_collection.py`）：D0-4、D0-5，以及 A 版或 B 版那几条，按选中的版本跑，没选中的那版不跑。界面需要提供这些标识：
  - 拒绝原因 `data-gild-reason`
  - 差额 `data-dust-short`（只有 A 版需要）
  - 常显那行 `data-gild-need` 和 `data-gild-have`
  缺哪个就标「缺接口」并跳过，跳过不算通过。
- 跑法、期望退出码和 REGRESSION.md 第 3 步、第 4 步一样。新增条数落地后按实测，同步进 accept.sh 和 COUNTS-B.md。
- 拍板项还是杨总那条「差额写不写」。没拍之前，A、B 两版都只是预备。
