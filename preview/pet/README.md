# 宠物原型 p3 / p4（preview/pet/）

> **p4**：小狗接进完整游戏流程 → `game/`（预览快照副本 + 小狗）。见下方「p4」。p4 需单独验收后才并主线。

独立页面：一只暖棕白小狗在房间里自己过日子。和正式游戏完全隔离：
- 只用自己的存档键 `tangzhe-pet-proto`；不读不写 `tangzhe-save` / `tangzhe-preview-save`；不接经济，收益加成 0。
- 家具目录只读 `../economy.js` 的 `FURNITURE`（200 件，占地 w×h 照用），真图用 `../art/furn_*.webp`。

## 文件
- `engine.js` 行为引擎（纯逻辑）：网格 A*（0.25 格分辨率）+ 精确线段拉直；碰撞 = 脚下圆（半径 0.22）+ 按朝向的身体盒（p3）；需求 / 状态机；球的物理；搬家具；存档 / 离线。
- `room.js` 测试房间摆设 + 「鼻尖位置 / 朝向 / 动作」互动配置（只有配了的家具才有专门互动：自己的窝、碗、3 个猫窝 / 猫吊床）。
- `art.js` 美术 manifest 校验 + 动画播放器；`art/manifest.json` 占位 manifest；`art/MANIFEST.md` 合同说明。
- `puppy.js` 占位小狗（程序绘制，按 manifest 原点和嘴巴锚点画）。
- `main.js` 页面：画布渲染、三个操作、搬家具、存档、测试钩子（`__pet`、`advanceTime`、`render_game_to_text`）。

## p2 修复（熊大 p1 复核）
- 叼着球被摸：先安全放球（在你面前就算送回）再被摸；任何计划被打断后嘴里还叼着球，下一个自主计划先原地放下，不会一直叼着、不用呼唤也能再抛。
- 读档精力只认有限数值，合法的 0 保留为 0（以前 `数值 || 70` 把 0 当缺失），再单独加离线休息；0 精力读档后是累的、会去休息。

## p3 修复（熊大 p2 复核）
- (a) 互动目标绑定家具 uid（同款两件也不认错）。布局一变（obsVer 变）就重算这件家具的互动站位：还在走 → 改道去新站位；已经在闻 / 守着 → 跟到新位置重新闻，旧位置不再闻；家具没了 / 新站位站不下 / 走不到 → 取消计划（愣一下换别的事）。
- (b) 读档先把存档里的整组布局放上，再统一查冲突：单件出界 / 压窝压碗回默认；两两重叠时每轮挑冲突最多的「不在默认位」的件回默认（平手优先回「默认位空着」的那件，再按 uid）。合法交换 / 三件轮换都保留，结果与存档记录顺序无关。
- (c) 碰撞按小狗实际外形：manifest 新增 `body`（E/N/S 每个朝向所有帧的左右像素范围，含鼻尖 / 尾巴尖 / 耳朵，逐帧量出），引擎换算成按朝向的身体盒（东：前 0.63 / 后 0.58 格；南北：左右约 0.28 格；纵深 ±0.22）。规划、走路、转身、东张西望、原地动作、叼球站位、搬家具（不能压到鼻子 / 尾巴）都按身体盒查；走动朝向按「这一段」定，和规划用同一条规则。互动站位按鼻尖反推，鼻尖贴边不进图。

## 已知限制 / 下一步
- 美术是占位（程序画），等真图集；动作节奏按占位时长调的。换真图时把 `manifest.body` 按真图逐帧外形改（e2e 会逐帧量占位图核对，真图要同样核对）。
- 小狗身长约 1.2 格：两件家具之间只有 1 格宽的竖向缝里转不了侧身，只能竖着走；要原地动作时会先挪到宽敞处。球停在这种窄缝里叼不到就放弃（随机抛球不往窄缝扔）。
- 猫窝 / 猫吊床左右只有 1 格空，改站在它前面偏左闻（画在家具前面）；自己的饭碗只按脚下圆算（吃饭时嘴伸到碗上）。
- 家具都按正面图画，房间里只用了不旋转的摆法；旋转后的占地已支持（测试覆盖），但没有侧面图。
- 只有一只狗、不跳上家具、没有饥饿 / 打卡提示（按规格）。
- 原型页（index.html）本身仍是独立页；接进游戏的是 `game/`（p4）。

## p4：接进完整游戏（`game/`）
入口：`preview/pet/game/?v=p4`。流程：商城（家宅 → 商城，第一张卡）买小狗 3000 金币 → 住进当前 CEO 的家宅 → 自己逛 / 闻猫窝 / 回窝睡 / 玩球，生活模式下呼唤 / 摸摸 / 抛球、点小狗 = 摸摸 → 刷新存档保留（短离开原地接着来，离开 ≥20 秒算在窝里睡了一觉，回精力不扣亲密）。
- **文件**：`game/index.html`、`app.js`、`economy.js`、`style.css` 是预览（当前 12c）的快照副本，`art/` 路径改成 `../../art/`，版本号 p4；改动只有小狗钩子（app.js 里搜「宠物 p4」）。`petgame.js` = 小狗接入层（存档字段 / 购买 / 家宅布局同步 / 画），`petgame.css` = 样式。生成脚本 `tools/game/mkgame.py`（钩子代码在 `tools/game/glue.js`，主线更新后重跑即可）：只替换资源路径、版本号、插入钩子，不动经济 / 存档 / 家具逻辑。
- **存档**：沿用游戏原来的键（`tangzhe-preview-save` / `-bak` / `-tab-lock`），**不新增、不改名任何键**；小狗只占存档里一个字段 `state.pet = { v:1, owned:true, home, boughtAt, eng }`（eng = 引擎存档：位置 / 精力 / 亲密 / 球，不含家具）。没有 `pet` 字段 = 没买，旧档照常读、读完也不多字段；坏字段删掉当没买；家没开放就搬回第一个开放的家。`E.migrate` 本来就保留未知字段，所以主线预览读写这份档也不会丢小狗（e2e 验过）。根目录 `app.js` 不动。
- **家具**：一律以家宅摆设为准，每帧比对，变了就 `engine.setLayout` 整组换上（uid 沿用，互动目标按 uid 跟）；升级房子尺寸一起换。家宅的摆放规则不认识小狗：家具摆到它脚下，它会挪到最近空地。布置模式下小狗停下等（`setRearrange`），按钮收起。
- **小窝**：不占家具格，自动找空地（优先左前角，平的能踩），被家具压住就换地方；屋里摆满放不下时画在左前角、小狗原地趴着睡。家宅里没有饭碗（`room.bowl = null`）。
- **画**：小狗 / 窝 / 球是 `#roomFloor` 里的绝对定位元素；地上家具按占地前沿写 `--fz`，小狗按落地点排，前后遮挡一致；CEO 小人在最上层。
- **换正式美术**：和原型共用 `art/manifest.json`。熊大的图集到了 = 图集放 `preview/pet/art/`，manifest 改 `placeholder:false`、`atlas.image` 指向文件名，帧序 / 锚点 / `body` 按真图改，代码不用动（e2e 用烘出来的图集模拟过这条路）。
